# Next: Add Clothing Upload MVP

## Goal

Build one complete Android vertical slice:

```text
Choose image
→ copy image into app-owned storage
→ save local clothing record in Room
→ upload through a fake POST API
→ update Room with backend ID and image URL
→ display the saved item
```

The real backend can later replace the fake remote implementation without changing the screen or ViewModel.

## Important Storage Decision

Do not store image bytes in Room.

- Room stores IDs, file paths, remote URL, timestamps, and upload status.
- App internal storage contains the local image file.
- Backend/object storage permanently contains the uploaded image.
- Coil displays local files now and remote URLs later.

## Implementation Order

### 1. Define the small MVP contract first

Create:

```text
domain/model/ClothingItem.kt
domain/model/UploadStatus.kt
data/dto/ClothingUploadResponseDto.kt
data/local/entity/ClothingEntity.kt
```

Use this MVP model:

```text
localId: String              UUID generated by Android
backendId: String?           returned by backend
userId: String
localImagePath: String       app-owned file path
remoteImageUrl: String?      returned by backend
uploadStatus: UploadStatus
createdAt: Long
```

Statuses:

```text
PENDING
UPLOADING
UPLOADED
FAILED
```

Keep the large production clothing attributes out of Room for this slice. Add them after the upload flow works.

### 2. Add dependencies

Add:

```text
Room runtime
Room KTX
Room compiler through KSP
Coil Compose
```

Do not add Hilt yet.

### 3. Implement local persistence

Create:

```text
data/local/entity/ClothingEntity.kt
data/local/dao/ClothingDao.kt
data/local/ClothingMapper.kt
```

Update:

```text
data/local/AppDatabase.kt
```

DAO operations:

```text
insert(item)
update(item)
observeAll(): Flow<List<ClothingEntity>>
findByBackendId(id)
deleteByLocalId(id)
```

Use a Room singleton created manually for now.

### 4. Implement app-owned image storage

Create:

```text
data/local/ClothingImageStorage.kt
```

Responsibilities:

```text
copy selected content URI into filesDir/clothing/
create a unique filename
return the saved absolute path
delete the local file when the clothing item is deleted
```

This avoids depending permanently on a temporary gallery URI.

### 5. Define repository and fake POST API

Update:

```text
repository/ClothingRepository.kt
```

Create:

```text
data/remote/ClothingRemoteDataSource.kt
data/remote/MockClothingRemoteDataSource.kt
repository/DefaultClothingRepository.kt
```

Repository operations:

```text
addClothing(selectedImageUri)
observeClothing()
retryUpload(localId)
deleteClothing(localId)
```

Fake POST behavior:

```text
delay about 1 second
return backendId such as cloth_<uuid>
return a fake remoteImageUrl
```

Repository workflow:

```text
copy image locally
insert Room row as PENDING
set status to UPLOADING
call fake POST API
on success, save backendId + remoteImageUrl + UPLOADED
on failure, save FAILED and retain local image
```

Later, replace only `MockClothingRemoteDataSource` with Retrofit multipart upload.

### 6. Implement ViewModel

Create:

```text
feature/closet/AddClothingUiState.kt
viewmodel/AddClothingViewModel.kt
```

UI state:

```text
selectedImageUri

saveCompleted
```

Events:

```text
ImageSelected
SaveClicked
RetryClicked
ErrorDismissed
SaveHandled
```

The ViewModel calls the repository only. It must not call Room or the fake API directly.

### 7. Build the screen

Update:

```text
view/closet/AddClothingScreen.kt
```

MVP UX:

```text
large image preview
Choose from gallery button
Replace/remove selected image
Add to wardrobe button
loading state while saving/uploading
success navigation
clear error message with retry
```

Use Android Photo Picker:

```text
ActivityResultContracts.PickVisualMedia
```

Do not add camera capture in this phase.

### 8. Add navigation

Update:

```text
navigation/Routes.kt
navigation/AppNavHost.kt
```

Add:

```text
Home → Add Clothing
Add Clothing → Home/Closet after success
```

The temporary Home screen needs an `Add clothing` button so the flow is testable.

### 9. Verify the vertical slice

Test:

```text
select an image
preview the selected image
save it
restart the app
confirm the image still appears from local storage
confirm Room contains localId and mock backendId
simulate upload failure
confirm FAILED state and retry work

```

Run:

```powershell
.\gradlew.bat assembleDebug
```

## Real Backend Swap Later

The backend should eventually expose:

```text
POST /v1/clothing
multipart image upload
```

Expected response:

```json
{
  "id": "cloth_123",
  "image_url": "https://storage.example.com/cloth_123.webp",
  "analysis_status": "processing"
}
```

When available:

1. Add Retrofit/OkHttp.
2. Implement a real `ClothingRemoteDataSource`.
3. Map its response DTO to the existing repository result.
4. Keep Room, ViewModel, screen, and navigation unchanged.

## Definition of Done

- User can choose one image from the gallery.
- The image is copied into app-owned storage.
- A Room record is created with a local UUID.
- Fake upload returns and stores a backend ID.
- Upload state is visible and persisted.
- The saved image survives app restart.
- The project builds successfully.
